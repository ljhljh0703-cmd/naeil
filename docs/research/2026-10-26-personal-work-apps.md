# 개인 작업판 화면 참고 카드

대상 앱: 혼자 개발하는 사람이 아침에 제일 먼저 여는 작업판. 오늘 화면 4영역(지금 할 것 1개 / 마지막에 한 일 / 내가 정할 것 / 마감 가까운 것) + 프로젝트별 마일스톤 화면. 맥 위주, 가끔 폰. 전부 되돌릴 수 있어 실수 비용 낮음.

표기: (추론) = 공식 문서에 없고 캡처·정황으로 판단한 것. 확인 못 함 = 찾지 못한 것.
조사일: 2026-10-26. 캡처는 전부 1440px 폭 브라우저 화면, 같은 폴더 `captures/` 아래.

### Things 3 · Today (This Evening 포함)
- 성격: 개인 1인 / 하루 여러 번(아침에 한 번 정리, 이후 돌아올 때마다 맨 위 항목 확인) / 적음: 공식 이미지 기준 오늘 일정 5줄 + 할 일 5개 + 저녁 할 일 3개 / 낮음(체크 해제, 날짜 다시 지정 가능)
- 첫 화면: 별 아이콘과 "Today" 제목 아래 할 일 목록. 캘린더를 연결하면 목록 위에 오늘 일정 상자가 붙음
- 배치: 왼쪽 목록 사이드바(창 폭 약 1/4, 추론) + 오른쪽 본문 한 칸. 본문은 위에서 아래로 일정 상자 / 오늘 할 일 / 달 아이콘 "This Evening" 구분선 아래 저녁 할 일. 할 일 한 줄은 제목 + 그 아래 작은 회색 글씨로 소속 프로젝트, 마감이 오늘이면 줄 오른쪽 끝에 빨간 깃발과 "today"
- 주 동작 흐름:
  1. 아침에 목록을 훑음
  2. 오늘 안 할 것은 날짜를 다시 고름(맥에서 ⌘S로 날짜 선택 창)
  3. 할 순서대로 끌어서 정렬
  4. 하루 중 돌아올 때마다 맨 위 항목을 집음
  5. 끝낸 건 체크, 못 끝낸 건 다른 날로 옮김
- 기다림·빈 화면·오류: 빈 Today 모양은 확인 못 함. 남의 답을 기다리는 일은 Today에서 빼고 "Waiting" 태그를 붙여 나중 날짜나 Someday로 보내라고 공식 안내함. 동기화 오류 표시는 확인 못 함
- 글자·간격: 공식 화면은 이미지(래스터)라 px 측정 확인 못 함. 이미지상 제목 글씨가 할 일 글씨의 약 2배, 할 일 줄 높이가 고르게 맞춰져 있음(추론)
- 따라 할 것: ① "맨 위에 있는 걸 집는다"는 사용 규칙. 순서가 곧 다음 할 일이므로, 우리 "지금 할 것" 자동 선택과 같은 생각이고 "오늘 고정"은 순서 맨 위로 끌어올리기로 만들면 됨 ② 저녁 구역처럼 "있긴 한데 지금은 아님"을 구분선 아래 작게 두는 방식. "마감 가까운 것"을 화면 아래쪽에 낮은 존재감으로 둘 때 참고
- 피할 것: 기다리는 일을 태그 검색으로만 찾게 하는 방식. 우리 앱은 "내가 정할 것"을 화면에 직접 꺼내 보여야 함
- 캡처 볼 곳: https://culturedcode.com/things/support/articles/4001304/ (본문 첫 이미지가 Today 화면) / 저장본 `captures/things.png`

### Todoist · Today
- 성격: 개인~소규모 팀 / 하루 여러 번 / 중간: 모든 프로젝트에서 오늘 날짜가 붙은 할 일이 한 목록에 모임 / 낮음
- 첫 화면: "Today" 제목과 바로 아래 할 일 개수(예: 6 tasks), 그 밑 동그라미 체크 + 제목 줄 목록. 1순위 할 일은 빨간 동그라미로 맨 위
- 배치: 왼쪽 사이드바(추가·검색·받은 목록·Today·프로젝트) + 가운데 목록 한 칸. 오른쪽 위 보기 버튼으로 목록/보드/캘린더 전환. 캘린더 보기에서 "Plan"을 누르면 옆 칸에 지난 할 일·종일 할 일·시간 잡힌 할 일이 모임
- 주 동작 흐름:
  1. 오늘 가장 중요한 3개에 1순위를 붙임(공식 권장)
  2. 너무 많으면 이번 주 뒤쪽으로 미룸
  3. 지난 할 일은 내일이나 이번 주로 미룸(반복 할 일은 항상 내일로)
  4. 목록 보기에서 할 일을 맨 아래로 끌면 내일로 넘어감(정렬·묶기를 끈 상태일 때만)
  5. 동그라미를 눌러 완료, "완료한 할 일 보기"를 켜면 오늘 한 일이 보임
- 기다림·빈 화면·오류: 날짜 없는 할 일은 Today에 아예 안 뜸(공식). 빈 화면 모양은 확인 못 함. 지난 할 일 묶음의 이름·버튼 모양은 도움말 본문에서 확인 못 함
- 글자·간격: 도움말 화면은 이미지라 확인 못 함
- 따라 할 것: ① 제목 바로 아래 남은 개수 한 줄. 4영역마다 제목 옆에 개수를 붙이면 열자마자 양이 보임 ② "끌어서 맨 아래 = 내일" 같은 한 동작 미루기. 우리 "건너뛰기"도 확인 창 없이 한 번에 처리하고 되돌리기만 남기면 됨
- 피할 것: 날짜가 없으면 안 보이는 규칙. 우리 "지금 할 것"은 마감 없는 진행 중 작업이 1순위 후보라 날짜로 거르면 빠짐
- 캡처 볼 곳: https://www.todoist.com/help/articles/how-to-plan-your-day-UVUXaiSs ("Set task priorities" 아래 이미지) / 저장본 `captures/todoist.png` (사이트 위쪽 안내 띠가 일부 가림)
- 출처: https://www.todoist.com/help/articles/how-to-plan-your-day-UVUXaiSs · https://www.todoist.com/help/articles/use-the-board-layout-in-todoist-AiAVsyEI

### Linear · My issues(Assigned 탭) + Inbox
- 성격: 팀 개발자 / 하루 여러 번 / 많음: 상태별 묶음 아래 이슈 번호·상태 아이콘·제목이 한 줄씩 / 낮음~중간(상태 변경은 되돌릴 수 있음, 활동 기록에 되돌리기 버튼)
- 첫 화면: Assigned 탭의 상태별 묶음 목록. 묶음 머리마다 상태 이름 + 개수(In Review 1, In Progress 1, Backlog 1 식)
- 배치: 왼쪽 사이드바(Inbox, My issues, 작업공간 목록) + 가운데 목록. 목록 위에 탭 4개(Assigned/Created/Subscribed/Activity)와 필터 줄, 오른쪽 위 보기 설정. 홈페이지 재현 화면에서 이슈를 열면 가운데 본문 + 그 아래 활동 기록 + 오른쪽 속성 칸(약 300px, 측정 좌표로 계산한 추론)
- 주 동작 흐름:
  1. G 다음 M으로 My issues 열기
  2. 위에서부터 묶음 순서대로 봄: 급한 일 → 기한 걸린 일 → 막고 있는 일 → 이번 주기 일 → 그 밖의 진행 중 → 분류 대기 → 백로그 → 완료
  3. 같은 묶음 안에서는 우선순위 순, 이미 시작한 것이 먼저
  4. 알림은 Inbox(G 다음 I)에서 J/K로 넘기고 H로 나중에 다시 보기, U로 읽음 처리
  5. Inbox의 Priority 탭(2026-09 추가)에서 "지금 봐야 할 알림"만 따로 봄
- 기다림·빈 화면·오류: 묶음은 해당 이슈가 있을 때만 나타남(공식). 빈 탭 화면은 확인 못 함. 미뤄 둔 알림은 정한 시각에 Inbox로 다시 올라옴
- 글자·간격: linear.app 첫 페이지에 HTML로 다시 그린 앱 화면이 있어 getComputedStyle로 측정함(실제 앱 아닌 홈페이지 재현본). 글꼴 Inter Variable / 사이드바 항목 13px, 굵기 510, 행 높이 28px, 행 간격 30px / 사이드바 묶음 이름 12px 회색(rgb 98,102,109) / 이슈 본문 14px, 줄높이 21px / "Activity" 제목 16px, 굵기 590, 줄높이 28px / 활동 기록 한 줄 12px, 줄높이 14~16.8px, 시간 표시("2min ago") 같은 크기 회색
- 따라 할 것: ① "진행 중 먼저, 그다음 우선순위" 정렬과 "해당될 때만 나타나는 묶음". 우리 "지금 할 것" 선정 규칙과 거의 같고, 비어 있는 영역은 숨기거나 한 줄로 접는 근거로 씀 ② 활동 기록 한 줄 형식: 누가(사람·Slack·자동 분류 기능·에이전트) + 무엇을 + 언제, 끝에 되돌리기 버튼. 재현본에 "에이전트가 바꾼 파일 2개, 내 검토를 기다리는 초안 PR" 줄이 있어 "마지막에 한 일"의 Claude/Codex 줄과 "내가 정할 것" 연결에 그대로 참고 가능
- 피할 것: 탭 4개 + 묶음 8종이라는 정보량. 혼자 쓰는 아침 첫 화면에는 많음
- 캡처 볼 곳: https://linear.app/docs/my-issues (첫 이미지) · https://linear.app/docs/inbox (Priority/Other 탭 이미지) · https://linear.app/ (첫 화면 아래 HTML 재현 앱) / 저장본 `captures/linear.png`

### Sunsama · 하루 계획 + Today view + Focus mode
- 성격: 개인 사무직·개발자 / 아침 1회 계획 후 하루 종일 띄워 둠 / 중간: 할 일 카드 열 + 오늘 캘린더 / 낮음
- 첫 화면: 계획 단계 첫 질문 "오늘 무엇을 끝낼까"와 할 일 추가 칸. 계획이 끝난 뒤 띄워 두는 Today view는 할 일 한 열 + 오른쪽 캘린더
- 배치: 왼쪽 내비는 기본 숨김(< 키나 왼쪽 끝 마우스로 꺼냄) + 가운데 할 일 카드 열(카드마다 시작 시각, 예상 시간, 채널 태그, 연동 앱 아이콘) + 오른쪽 캘린더 + 맨 오른쪽 연동 앱 아이콘 세로줄(캡처 기준). 도움말은 Today view를 "두 칸 화면"이라 부름
- 주 동작 흐름:
  1. (어제 마무리를 안 했으면) 어제 남은 일부터 완료 처리·수정
  2. 오늘 할 일 넣기: 회의 가져오기, 백로그·연동 앱에서 끌어오기, 예상 시간 붙이기
  3. 예상 시간 합계가 설정 기준을 넘으면 경고. D로 다른 날, Z로 백로그
  4. 순서를 정하고 필요하면 캘린더에 시간 배치, 퇴근 시각 확인
  5. 일하는 동안 F로 집중 모드: 한 작업만 전체 화면, 완료하면 다음 작업으로 자동 이동
- 기다림·빈 화면·오류: 오늘 작업을 모두 끝내면 "Done for the day" 화면(공식). 못 끝낸 일은 자정에 다음 날로 자동 이월, 여러 날 연속 이월되면 자동 보관되고 보관함 아이콘에 배지(공식). 오후 3시 이후에 계획을 열면 내일 계획으로 잡힘(공식)
- 글자·간격: 공식 화면은 이미지라 확인 못 함
- 따라 할 것: ① 집중 모드의 "완료하면 다음 작업이 자동으로 올라오고, 다 끝나면 끝 화면". 우리 "지금 할 것"에서 완료 누르면 다음 후보 자동 채우기, 후보가 없으면 짧은 안내 문구 ② 오래 이월된 일을 따로 걸러 내는 장치. 우리는 "건너뛰기"가 반복된 작업에 횟수를 붙여 보이면 됨(이월 횟수 표시는 Sunsama 문서에 없음, 우리가 더하는 부분)
- 피할 것: 매일 아침 5단계 계획 절차를 거치게 하는 구조. 우리 앱은 자동 선택이 핵심이라 단계형 진행 화면이 필요 없음
- 캡처 볼 곳: https://www.sunsama.com/features/daily-planning-and-shutdown (첫 큰 이미지) / 저장본 `captures/sunsama.png`

### TickTick · Today 목록 (+ Kanban·Timeline 보기)
- 성격: 개인 / 하루 여러 번 / 중간: 날짜 묶음(Today/Tomorrow) 아래 할 일 줄 + 오른쪽 상세 / 낮음
- 첫 화면: 날짜 묶음 머리 "Today 4"와 그 아래 할 일 줄, 줄 오른쪽 끝에 시각(07:00 식). 캡처는 Today가 아닌 Inbox 화면이지만 같은 날짜 묶음이 보임
- 배치: 맨 왼쪽 기능 아이콘 세로줄(약 50px, 추론) + 목록 사이드바(Today·Tomorrow·Next 7 Days·Assigned to Me·Inbox, 이름 옆 숫자) + 가운데 목록 + 오른쪽 상세 칸(제목, 메모, 체크리스트). 세 칸 + 아이콘 줄
- 주 동작 흐름:
  1. 사이드바에서 Today를 누름
  2. 목록 위 "Add task" 한 줄에 바로 입력
  3. 할 일에서 오른쪽 클릭 → "Start Focus" → 뽀모도로나 스톱워치 선택
  4. 체크로 완료
  5. 계획이 바뀌면 칸반 보기로 바꿔 다른 열로 끌기
- 기다림·빈 화면·오류: 집중 시간은 기기 간 동기화 설정을 켜면 한 기기에서 시작·정지한 게 다른 기기에도 반영(공식). 지난 할 일 묶음과 미루기 버튼은 공식 문서에서 확인 못 함. 빈 화면 확인 못 함. Today·Tomorrow·Next 7 Days 목록은 Timeline 보기를 지원하지 않음(공식)
- 글자·간격: 홈페이지 화면이 이미지라 확인 못 함
- 따라 할 것: ① 사이드바 이름 옆 숫자(Today 11, Tomorrow 7). 영역별 개수를 작은 회색 숫자로 ② 할 일 줄에서 바로 시작 + 폰·PC 동기화. 맥에서 "시작"을 누르면 폰에서도 진행 중으로 보이게
- 피할 것: 세 칸 + 아이콘 줄 + 습관·매트릭스·카운트다운까지 한 앱에 모은 구성. 아침 첫 화면으로는 산만함

### Llama Life · 메인 목록 + 타이머 (한 번에 하나)
- 성격: 개인(제작자가 ADHD 진단 뒤 직접 만들었다고 소개) / 하루 종일 켜 둠 / 아주 적음: 큰 타이머 하나 + 아래 할 일 카드 / 낮음
- 첫 화면: 목록 맨 위 할 일이 자동으로 들어간 큰 원형(파이) 타이머 또는 큰 숫자 타이머와 재생 버튼
- 배치: 폰 기준 한 열. 위에서부터 목록 총 시간("1h 10m")·끝나는 시각("4:00pm") 줄 / 큰 타이머와 -5·+5분 버튼 / 할 일 카드 목록(카드마다 남은 시간, Delete, Top 또는 Reset, Complete). 데스크톱 배치는 공식 GIF만 있어 글로 확인 못 함
- 주 동작 흐름:
  1. 할 일을 넣고 분을 적음(안 적으면 25분)
  2. 맨 위 할 일이 타이머에 자동으로 올라감
  3. 재생
  4. 시간이 다 되면 알람, 이어서 초과 시간이 위쪽에 따로 올라감
  5. Complete를 누르면 다음 할 일로. 지금 못 할 일은 "Not-Now" 두 번째 목록으로 보냄
- 기다림·빈 화면·오류: 시간 초과 시 "Overtime" 표시가 타이머 위에서 계속 셈, 끝낼 때 그 시간을 더할지 지울지 고름(공식). 빈 화면 확인 못 함. Safari에서 타이머 소리가 안 나는 문제와 해결법이 도움말에 따로 있음
- 글자·간격: 홈페이지 화면이 이미지라 확인 못 함
- 따라 할 것: ① 맨 위 하나가 화면에서 가장 큰 자리를 차지하고 나머지는 작은 카드. 카드의 "Top" 버튼은 우리 "오늘 고정"과 같은 역할 ② "Not-Now" 두 번째 목록 + 하나씩 "Do now", 전부 "메인으로 옮기기". 건너뛴 작업을 버리지 않고 모아 두고, 들인 시간도 그대로 유지
- 피할 것: 할 일마다 시간 입력을 기본으로 요구하는 흐름. 개발 작업은 예상 시간이 자주 틀려(추론) 우리 앱에선 시간 칸을 선택 사항으로

## 마일스톤 화면 쪽 참고 메모
- Linear 프로젝트 마일스톤: 프로젝트 설명 바로 아래 마일스톤 목록, 마일스톤마다 연결된 이슈 기준 완료율(시작하면 일부, 완료하면 전부 반영). 지금 향하는 다음 마일스톤만 노란 마름모. 타임라인에서 마름모를 끌어 날짜 이동, 여러 개 함께 이동, 날짜 오른쪽 클릭으로 추가. 목표 날짜는 나중에 넣어도 됨
- TickTick Timeline: 목록을 가로 시간축으로 보여 줌, 일·주·월 확대 전환. 시간이 안 정해진 일은 오른쪽 "Schedule Tasks" 칸에 모였다가 끌어서 배치
- Todoist 보드: 프로젝트 섹션이 곧 열, 섹션 없는 일은 기본 열. 섹션을 프로젝트 단계로 쓰라는 공식 안내
- Things: 사이드바에서 프로젝트 이름 옆 원 아이콘이 진행만큼 채워짐(공식 Today 이미지 기준)

## 확인 못 한 것
- 빈 화면 모양: Things, Todoist, Linear, TickTick, Llama Life 모두 공식 문서에서 찾지 못함(Sunsama만 "Done for the day" 확인)
- 지난 할 일 표시 방식: Things와 TickTick은 공식 문서에서 확인 못 함, Todoist는 미루기 규칙만 있고 묶음 이름·버튼 모양은 확인 못 함
- px 측정: Linear 홈페이지의 HTML 재현본만 측정함. 실제 Linear 앱, 나머지 5개 제품은 공개 화면이 모두 이미지라 측정 못 함
- Akiflow: 공식 도움말 문서를 찾지 못해(홈페이지 광고 문구만 있음) 근거가 더 많은 TickTick으로 바꿈. 참고로 Akiflow 홈페이지 재현 화면은 글씨 14.4px, 굵기 500, 항목 간격 8px로 측정됨
- TickTick Today 화면 자체 캡처: 공개 페이지에서 찾지 못해 Inbox 화면(같은 날짜 묶음 구조)으로 대신함
- Llama Life 데스크톱 배치와 단축키 목록: 공식 도움말이 GIF·이미지로만 보여 줌
- 폰 화면 배치: Llama Life 말고는 폰 화면을 따로 보지 못함
- Linear "에이전트가 바꾼 파일 2개" 활동 줄이 실제 앱에도 같은 모양으로 있는지 확인 못 함(홈페이지 재현본에서만 봄)
