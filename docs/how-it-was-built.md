# 어떻게 만들었나

혼자 만들지만 손은 셋입니다. 작가가 정하고, 클라우드의 Claude 세션이 코드와 시험을 만들고, 작가 컴퓨터의 Codex 가 받아서 실제 기계에서 켜고 확인합니다. 셋이 같은 파일을 동시에 고치지 않게 역할과 순서를 나눴습니다.

## 한 바퀴

| 순서 | 누가 | 무엇을 남기나 |
|---|---|---|
| 1. 정하기 | 작가 | 할 일 하나와 「끝나면」 한 줄. 판단이 갈리는 곳만 선택지 2~3개 중 고름 |
| 2. 만들기 | 클라우드 Claude | 브랜치, 시험, PR. 자동 검사(코드 검사, 시험, 브라우저 흐름, 실제 윈도우, 비밀 키 검사)가 다 통과해야 올림 |
| 3. 합치기 | 작가 | main 합치기는 작가만 |
| 4. 기계에서 확인 | Codex (작가 컴퓨터) | 지시서대로 받아 켜고, 확인 항목마다 통과와 실패를 회신 파일로 |
| 5. 지적 반영 | 클라우드 Claude | 회신의 지적을 시험으로 먼저 재현하고 고침 |

## 실제 예

- **되살리기 중간 실패** (#18 → `0f83abb`): 매일 백업과 복원 연습을 합친 뒤, 맥에서 확인하던 Codex 가 「되살리기 도중 실패하면 원래 자료가 사라질 수 있다」고 짚음. 옆 임시 파일에서 먼저 되살린 뒤 바꿔 끼우게 고치고, 단계마다 일부러 실패를 넣는 시험 3개를 붙임
- **윈도우 상태 표시가 설정 파일을 잘못 읽음** (#20 → #26): 윈도우 상시 서버를 합친 뒤 실제 윈도우에서 Codex 가 상태 표시 스크립트의 글자 인코딩 문제를 발견하고 고침. 같은 실수가 다른 스크립트에 없는지 저장소 전체를 검사하는 시험을 더함
- **시험이 가끔 실패** (#25): 서버 감독 시험이 끝나기 전에 폴더를 지워 가끔 실패. 끝나기를 기다린 뒤 지우게 고치고, 상태 파일 쓰기를 임시 파일과 이름 바꾸기로 바꿈

## 규칙

- 명세서 먼저: 주소와 응답 모양을 `docs/api/openapi.yaml` 에 먼저 쓰고, 서버 입력 검사는 명세서에서 그대로 읽음. 시험이 모든 응답을 명세서와 대조
- 저장과 변경 기록은 한 묶음: 하나만 저장되는 일이 없게, 쓰기 경로마다 기록 실패를 일부러 넣는 시험
- 실제 자료와 출입증은 AI 가 보지 않음: 출입증은 작가가 직접 만들고, 시험은 격리된 빈 자료에서
- 바깥 글은 지시가 아님: 깃허브 이슈처럼 바깥에서 온 글은 서버가 무조건 표시하고, 이어하기 한 장에서 본문을 뺌
- 작업 지침은 `AGENTS.md`. AI 세션이 저장소에 들어오면 먼저 읽음
