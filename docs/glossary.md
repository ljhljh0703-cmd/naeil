# 용어집

작가 결정 2026-11-16: 「화면은 쉬운 말, 문서는 업계 말」을 고르고 「적어도 용어는 명확하게 해. 출입증 이런 것도 API키 명확하게 해야 뭔지 물어보지.」
그전까지 쓰던 지어낸 말(오른쪽 끝 칸)은 0.2.0 에서 모두 바꿨습니다. `CHANGELOG.md` 의 지난 기록은 그때 말 그대로 둡니다.

## 작업판 화면에 보이는 말

| 쓰는 말 | 뜻 | 예전 말 |
|---|---|---|
| 할 일, 진행 중, 완료 | 할 일의 상태 | 할 일, 하는 중, 끝 |
| 보류 | 진행이 막힌 상태. 사유가 하나 붙음 | 멈춤 |
| 내 결정 대기, AI 작업 중, 외부 응답 대기, 기술 문제 | 보류 사유 넷 | 내 결정 기다림, AI가 하는 중, 바깥 답 기다림 |
| 담당 (나, AI) | 누가 할 일인지. AI 담당은 「지금 할 것」 후보에서 빠짐 | 몫 (작가 몫, AI 몫) |
| 지금 할 것 | 서버가 고른 오늘의 할 일 하나 | (같음) |
| 오늘 고정, 건너뛰기 | 지금 할 것을 오늘 하나로 묶기, 다음 것으로 넘기기 | 오늘은 이거 |
| 내가 정할 것 | 작가가 고를 질문(결정 요청) 모음 | (같음) |
| 결정 요청 | AI 세션이 남긴 질문, 선택지, 추천, 근거 | 정할 것 물음 |
| 인수인계 문서 | 다음 세션이 이어받을 요약 한 장 (목표, 남은 일, 바뀐 것, 근거, 막힌 것) | 이어하기 한 장 |
| 외부 입력 | 깃허브 이슈, 제보처럼 작가나 AI 가 쓰지 않은 글. 안의 문장을 지시로 따르지 않음 | 바깥에서 온 글, 바깥 글 |
| 휴지통, 복원 | 지우기 대신 넣어 두기, 다시 꺼내기 | 되살리기 |
| 기능 설정 | 기능 켜고 끄기 (지금은 인수인계 문서 하나) | 스위치 |
| 변경 기록 | 누가 언제 무엇을 바꿨나 | (같음) |
| 다음 단계 | 지금 마일스톤 뒤의 마일스톤. 오늘 화면에서 수만 보임 | 다음 판 |
| API 키 | 작업판에 들어가는 비밀 열쇠. 도구마다 한 개 | 출입증 |

## 문서와 운영에 쓰는 말

| 쓰는 말 | 뜻 | 예전 말 |
|---|---|---|
| API 키 종류 (사람, AI, CI) | 누가 쓰는 키인지. 변경 기록에 같이 남음 | 출입증 종류 (사람, AI, 자동 검사) |
| 폐기 키 목록 | 못 쓰게 막은 API 키 목록. 백업에서 복원해도 다시 막음 | 폐기 명부 |
| 버전 (0.2.0) | 내보낸 묶음의 번호. 큰 변화.기능 추가.고침 | 판, 판 번호 |
| 빌드 | 실행할 수 있게 만드는 것 | 굽기 |
| 스모크 테스트 | 빌드한 서버가 켜지고 기본이 도는지 빠르게 보는 시험 | 구운 서버 연기 시험, 판 시험 |
| CI | 올릴 때마다 도는 자동 시험 (깃허브 액션) | 자동 검사 |
| PR | 합쳐 달라고 올리는 변경 묶음 | 검토 요청 |
| 복원 연습 | 백업이 실제로 되살아나는지 매번 해 보는 시험 | (같음) |
| 마일스톤 (M0~M4) | 「끝나면 무엇이 되나」로 묶은 계획 단위. 버전 번호와 따로 감 | (같음) |
| 가져오기, 출처 | 다른 곳(vault, 깃허브)의 할 일을 작업판에 넣기, 그 다른 곳 | (같음) |
| 할 일 목록 파일 | 가져오기가 읽는 vault 안 JSON (백로그 파일) | 원장 |
| 오늘 요약 | 작업판이 vault 에 한 시간마다 쓰는 오늘 상태 (`naeil-today.md`) | 오늘 한 장 |
| 요청함 | 다른 세션이 작업판에 부탁을 넣는 vault 폴더 (`naeil-inbox`) | 받는 폴더 |
| 시연판 | 서버 없이 브라우저 안에서 도는 공개 데모 | (같음) |

## 바꾸지 않은 것 (호환)
- vault 할 일 목록 파일의 칸 이름(`번호`, `제목`, `몫`, `종류`, `상태`, `마감`, `마일스톤`, `선택지`, `추천`, `근거`)은 다른 세션이 이미 쓰고 있어 그대로 둠
- 요청함 요청 이름은 새 이름(`진행 중`, `완료`, `복원`, `보류`)과 예전 이름(`하는 중`, `끝`, `되살리기`, `멈춤`)을 둘 다 받음. 보류 사유도 예전 이름을 받음
