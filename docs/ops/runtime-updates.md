# Node·라이브러리 보안 업데이트 (사내망·폐쇄망 기준)

사내망 서버는 인터넷에서 바로 업데이트를 받지 못한다고 가정한다. 그래서 「알기 → 들여오기 → 시험 → 바꾸기 → 되돌리기」를 정해진 순서로 한다.

## 지금 있는 장치 (단계 1)
| 장치 | 파일 | 하는 일 |
|---|---|---|
| 버전 고정 | `.node-version` | 내 맥 · 자동 검사(CI) · 나중 컨테이너가 같은 Node 를 쓴다 |
| 설치 막기 | `.npmrc` `engine-strict=true` + `package.json` `engines` | 낮은 Node 로는 `npm ci` 부터 실패 |
| 켜기 막기 | `src/runtime.ts` | 줄별 최소 안전 버전보다 낮거나 지원이 끝난 줄이면 서버를 켜지 않음 |
| 꾸러미 고정 | `package-lock.json` · `npm ci` | 꾸러미 버전과 지문을 잠근 그대로 설치 |
| 알림 | Dependabot | 꾸러미 업데이트 요청 자동 |

## 새 보안 공지가 나오면
1. **알기**: Node 보안 공지(nodejs.org → Blog → Vulnerability)와 Dependabot 알림을 본다. 지원 줄(22·24·26)과 내 서버가 쓰는 기능(바깥 HTTPS 요청, 압축, 권한 모델, 단일 실행 파일)에 걸리는지 표로 적는다
2. **고치기**: `src/runtime.ts` 의 줄별 최소 버전과 `.node-version` 을 새 수정 버전으로
3. **시험**: `npm run check` 통과 (최소 버전 시험 포함)
4. **들여오기** (단계 2부터): 인터넷 되는 기기에서 Node 설치 파일·컨테이너 이미지·꾸러미를 받고, 공식 지문(SHASUMS256)과 맞춰 본 뒤 사내 저장소로 옮긴다
5. **바꾸기** (단계 2부터): 개발용 서버에서 먼저 띄워 보고, 실제용 교체. 이전 이미지는 보관
6. **되돌리기**: 문제가 생기면 이전 이미지로. 무엇이·왜·뭘 바꿨나를 장애 기록에 남긴다
